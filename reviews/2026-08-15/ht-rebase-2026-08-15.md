# Adversarial review: `gems/diamond/ht-rebase-2026-08-15`

Snapshot reviewed: `0f614d6ff0a9301d8f6344671dd2cb7508f22c5d` against `ht-pre-rebase-2026-08-15` (`6e497a417385af7eece500072e97080fa3ab781c`). The snapshot contains nine replay commits; the obsolete decode squash is classified as superseded. The Pascal docs/harness group is now committed and included in this review.

## CLAIMS

- **CONFIRMED — infrastructure/UI ownership was replayed.** Compared the first old and new grouped commits. Every file added by `5b7a1e0a3` exists at `65e16cbe4`. Product UI source remains removed. The four old deleted files now present (`tools/ui/CMakeLists.txt`, `embed.cpp`, and the two PWA configs) are the current prebuilt-bundle glue, not restored product source.
- **REFUTED — TurboQuant was preserved as an equivalent format.** The CPU/CUDA types, codebooks, GET/SET_ROWS, FA vector kernels, quantize CLI, llama-bench parsing, and focused tests exist. However, persisted tensor IDs changed from TBQ3/TBQ4 42/43 to 43/44 because upstream assigned 42 to Q2_0. No metadata/version guard exists, so old TBQ3 data is read as Q2_0 and old TBQ4 data as the new TBQ3 layout. This can produce plausible garbage instead of a loud incompatibility error.
- **UNPROVEN — replacing TBQ's private rotation with the shared KV rotation removes the double transform without changing other supported uses.** The direct FA tests do not execute the KV-cache rotation graph. More importantly, the universal row codec no longer applies/inverts TurboQuant's dense rotation while whole-model TBQ3/TBQ4 remain exposed by `llama-quantize`; model weights do not traverse the KV rotation graph. No converted-model quality or compatibility test covers that joint. The old exported dense-rotation helpers and their QR/cache implementation also remain compiled but have no callers.
- **UNPROVEN — the final P5200 gates prove the replay commits.** I inspected external group-2 logs showing a final 22/22 focused CUDA pass and 53/53 code-test pass, and external group-4 reports/logs showing a 53/53 code-test pass plus exact-commit `bbe9cc764` Gemma smoke on a Quadro P5200. Those raw artifacts are outside the branch, so the results are unproven under the committed-raw-data rule. The smoke benchmark uses F16 K/V and therefore does not exercise TurboQuant.
- **UNPROVEN — the old DFlash/MTP squash is wholly superseded.** Current upstream contains broader `draft-mtp` and `draft-dflash` engines, Gemma4 NextN graphs, DFlash model/loader code, extraction interfaces, and auto-download support. But eight old exported DFlash symbols are absent, and the dedicated 11-check `test-dflash` target has no direct replacement. The current code gate compiles DFlash but does not prove that its speculative branch is reached.
- **REFUTED — the router/fit replay is ready for admission use.** The router, LoRA discovery, developer-role remap, API-prefix handling, checkpoint budget, Responses truncation status, queue cleanup, fit-plan CLI, and associated tests are present. However, a one-GPU fit that succeeds by reducing context returns before populating the plan and is serialized as zero devices/zero bytes. The reported one-device direct check exercises a different exit and does not cover this branch.
- **REFUTED — the checkpoint setting is a maximum host-RAM budget.** The committed post-capture eviction repairs aggregate overshoot when older checkpoints exist, but intentionally retains the newest checkpoint when it alone exceeds the cap. That is incompatible with the CLI's “max host-RAM budget” contract, and the best-effort test never asserts the post-create byte invariant.
- **REFUTED — the synchronous model lifecycle hardening has closed its quiet/hanging paths.** The committed route now rejects a missing/non-ready post-load model, fixing the staged false-success path. But a concurrent `models_max` capacity rejection is still a plain runtime error/500 rather than the new retryable 503, and unloading a `DOWNLOADING` model waits forever after cancellation reaches `DOWNLOADED` rather than `UNLOADED`.
- **REFUTED — the newer router admission group reserves the candidate's GPU demand.** The router-facing wrapper converts the still-empty one-GPU reduced-context fit result into a system-GPU-sized vector of zeroes while preserving success. Admission also samples physical free memory without reserving concurrent `LOADING` demand, so parallel loads can observe the same free bytes. The queued reservation work remains necessary.
- **UNPROVEN — DFlash sizing is runtime-correct.** The trained block-size accessor is now shared by context sizing and the speculative engine and malformed strings fall back loudly. It is declared only in `src/llama-ext.h`, not restored in the public `include/llama.h` surface, and no DFlash model/drafter was mounted; the new path was not reached end to end. CUDA Pool1D is source-complete for contiguous F32 and external focused results report 48 passing cases, but the raw evidence is not committed.
- **UNPROVEN — LocateAnything projector support is correct.** Projector registration, tensors, preprocessing, KimiVL graph selection, GELU-ERF, position handling, and token accounting are present. No LocateAnything mmproj/model was available, so the projector-specific graph was never executed; generic mtmd and CUDA tests prove compilation and unrelated paths, not model correctness.
- **REFUTED — termd's hard sandbox and wipe contracts are established.** The replay adds the complete Rust sidecar, a locked dependency graph, authentication, runsc/network checks, UUID ownership checks, and failure cleanup. However, the iptables parser accepts DROP rules even when an earlier ACCEPT/RETURN makes them unreachable and ignores an IPv6 network path. DELETE suppresses scratch-removal failures while returning 204, and failed file provisioning still launches bootstrap against partial state.
- **UNPROVEN — termd has a controlled disk footprint.** No `df`, workspace/rootfs size, release-binary size, or persistent-scratch measurement is committed with the group. There is no request/file-size cap, terminal-count limit, scratch quota, or Docker storage limit, so persistent bind mounts and overlay writes can consume the host filesystem without violating admission.
- **UNPROVEN — the committed MLA LoRA conversion is preserved end to end.** Its three passing eager/lazy/invalid-shape tests validate the fused-KV factorization algebra, including the K transpose, but call the helper directly. They bypass the converter branch, hparam lookup, tensor-name mapping, GGUF emission, and adapter loading, so a runtime-unreachable or loader-incompatible integration can still pass.
- **UNPROVEN — the committed Pascal measurements establish the current branch.** The commit adds historical JSON and prose but not raw logs/responses for the replay snapshot. PR #163's historical `798cf6cbe` evidence recomputes to 24.0209 versus 56.4429 tok/s (2.35x), 276/333 draft acceptance, and 7,524/7,824 MiB plus 149.10/172.38 W peaks for its exact build/model pair. Its no-spec HTTP 500 is also genuine for that pair. On current `07e1fabad` with the mounted Q4_K_XL/Q8_0 pair, the same no-spec shape instead returned HTTP 200, produced no drafts, and loaded the drafter anyway. These are version/model-scoped observations, not a universal current behavior or proof for `0f614d6ff`.
- **REFUTED — the Pascal evidence helpers fail closed.** Reviewer reproduction selected `cuda` and observed exit 0 both with a nonexistent benchmark binary and with `/bin/false`; the script printed an empty summary and produced no result. `compare-dflash-weights.py` likewise returns 0 with zero compared tensors and silently skips missing, unmapped, and shape-mismatched tensors. A green process therefore does not establish any benchmark or parity evidence.
- **REFUTED — the DFlash target validator refuses truncated tensor data.** It proves only that the file reaches one byte past the highest tensor start offset, without using tensor type or dimensions. Its positive fixture declares one F32 scalar yet provides one byte and calls that structurally complete. All four metadata tests pass, but they validate this weaker contract; truncation within the final tensor is accepted while the sweep says truncated/stub GGUFs are refused.
- **REFUTED — the Pascal packaging instructions describe the current install and measured disk footprint.** Current generated CMake rules install the full versioned `libllama` and `libllama-common` chains, contrary to the guide's manual-copy premise. The recipe then wildcard-copies them, reconstructs links, and destructively reuses `/tmp/stage`. It also presents conflicting 816 MB versus 150–200 MB runtime sizes and exact archive/image/build/deployment numbers without a committed byte/member/timing manifest tied to one archive SHA and build commit.

## NEW-FAILURE-MODES

- Legacy TBQ GGUFs can be silently interpreted under different tensor layouts after the enum collision.
- The same TBQ enum now means shared-rotation cache-domain data in KV use and unrotated scalar-codebook data in whole-model quantization.
- Direct backend tests can stay green while the KV rotation/quantization/model graph joint is never reached.
- Removing old exported DFlash symbols can break downstream consumers at compile/link time; unlike the GGUF collision, this at least fails loudly.
- Keeping unused private-rotation APIs makes accidental reactivation/double rotation possible and retains unnecessary code/data paths.
- Performance smoke with F16 K/V can be misread as validation of the changed TBQ path.
- A single-GPU fit resolved solely by reducing context returns success with an empty byte plan, so an admission caller can treat a real GPU model as free.
- `load_models()` assigns the shared `discovered_adapters` vector before acquiring the mutex used by readers; concurrent reload/list/load is a C++ data race.
- The fallback tool-call scanner counts braces inside quoted JSON strings and clears all content after parsing only a valid prefix, misclassifying valid calls or dropping suffix text.
- Streaming Responses reasoning items omit the new `incomplete`/`completed` per-item status; the TinyLlama truncation test never constructs a reasoning item.
- A `/models/unload` request for a downloading model can block indefinitely because cancellation terminates at `DOWNLOADED` while the new wait accepts only `UNLOADED` or removal.
- The under-lock `models_max` contention check throws an untyped runtime error, so a retryable capacity race still returns 500 despite the new 503 error class.
- A checkpoint larger than the configured byte cap is deliberately retained, so the advertised hard per-slot maximum can still be exceeded by an arbitrary checkpoint size.
- The admission wrapper turns a missing GPU plan into explicit zero-byte reservations, making the earlier undercount look structurally valid.
- Concurrent loads can all admit against the same instantaneous free VRAM because `LOADING` reservations are not subtracted.
- An earlier ACCEPT/RETURN or ungoverned IPv6 path can bypass termd's existence-only IPv4 DROP-rule audit.
- termd can return successful deletion while persistent scratch data remains, and has no quota preventing scratch/container layers from filling disk.
- A failed termd file write skips remaining files but still starts bootstrap and returns a running terminal.
- MLA's committed unit test can pass even if the converter branch is unreachable or emits names/shapes the adapter loader rejects.
- A missing or failed explicitly selected Pascal backend exits 0 and renders an empty summary, allowing automation to record a measurement run with no evidence.
- A broken DFlash conversion can compare zero tensors and exit 0 because missing/unmapped/shape-mismatched tensors are skipped.
- A GGUF truncated after the first byte of its final tensor passes the target-sweep integrity gate.
- The packaging guide can recopy stale wildcarded libraries and can delete another process's fixed `/tmp/stage` directory; its archive can diverge from CMake's install manifest.

## VERDICT

**do-not-merge** for this snapshot. The rebase remains incomplete; persisted TBQ compatibility can fail silently; the model-quantization/KV-rotation joint is unresolved; DFlash API/test bodies are not accounted for; router admission still undercounts/races; termd's firewall, wipe, provisioning, and disk contracts are not established; and the newly committed Pascal evidence gates can exit green without evidence while its integrity, packaging, and disk claims are false or unproven. Re-review after those findings are fixed or explicitly retired with loud guards and after the remaining feature groups land.

**UPSTREAM: needs-split.** Generic candidates include admission accounting, alias/error/status fixes, CUDA Pool1D, DFlash metadata validation, mtmd projector support, and MLA conversion after an integration-level test, each as a focused single-concern change. TBQ/Pascal format policy, HT router/UI contracts, and the termd sidecar/security policy are fork-specific or require separate proposals; the aggregate rebase is not an upstreamable unit.
