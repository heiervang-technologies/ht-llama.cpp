## CLAIMS

- **CONFIRMED — infrastructure/UI ownership was replayed.** Compared the first old and new grouped commits. Every file added by `5b7a1e0a3` exists at `65e16cbe4`. Product UI source remains removed. The four old deleted files now present (`tools/ui/CMakeLists.txt`, `embed.cpp`, and the two PWA configs) are the current prebuilt-bundle glue, not restored product source.
- **REFUTED — TurboQuant was preserved as an equivalent format.** The CPU/CUDA types, codebooks, GET/SET_ROWS, FA vector kernels, quantize CLI, llama-bench parsing, and focused tests exist. However, persisted tensor IDs changed from TBQ3/TBQ4 42/43 to 43/44 because upstream assigned 42 to Q2_0. No metadata/version guard exists, so old TBQ3 data is read as Q2_0 and old TBQ4 data as the new TBQ3 layout. This can produce plausible garbage instead of a loud incompatibility error.
- **UNPROVEN — replacing TBQ's private rotation with the shared KV rotation removes the double transform without changing other supported uses.** The direct FA tests do not execute the KV-cache rotation graph. More importantly, the universal row codec no longer applies/inverts TurboQuant's dense rotation while whole-model TBQ3/TBQ4 remain exposed by `llama-quantize`; model weights do not traverse the KV rotation graph. No converted-model quality or compatibility test covers that joint. The old exported dense-rotation helpers and their QR/cache implementation also remain compiled but have no callers.
- **UNPROVEN — the final P5200 gate proves this commit.** I inspected external logs showing a final 22/22 focused CUDA pass, a 53/53 code-test pass, and an exact-commit `d71f5f5e1` llama-bench record on a Quadro P5200. Those raw artifacts are outside the branch, so the result is unproven under the committed-raw-data rule. The smoke benchmark uses F16 K/V and therefore does not exercise TurboQuant.
- **UNPROVEN — the old DFlash/MTP squash is wholly superseded.** Current upstream contains broader `draft-mtp` and `draft-dflash` engines, Gemma4 NextN graphs, DFlash model/loader code, extraction interfaces, and auto-download support. But eight old exported DFlash symbols are absent, and the dedicated 11-check `test-dflash` target has no direct replacement. The current code gate compiles DFlash but does not prove that its speculative branch is reached.

## NEW-FAILURE-MODES

- Legacy TBQ GGUFs can be silently interpreted under different tensor layouts after the enum collision.
- The same TBQ enum now means shared-rotation cache-domain data in KV use and unrotated scalar-codebook data in whole-model quantization.
- Direct backend tests can stay green while the KV rotation/quantization/model graph joint is never reached.
- Removing old exported DFlash symbols can break downstream consumers at compile/link time; unlike the GGUF collision, this at least fails loudly.
- Keeping unused private-rotation APIs makes accidental reactivation/double rotation possible and retains unnecessary code/data paths.
- Performance smoke with F16 K/V can be misread as validation of the changed TBQ path.
